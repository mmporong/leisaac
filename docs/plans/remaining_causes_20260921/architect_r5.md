# Architect 최종 검토: 남은 원인 3건 조사 계획 revision 5

## 최종 의견 (한 줄)

**2.2 진입 디스크 게이트를 9.5 GB에서 약 14.5 GB로 고치면 계획 전체가 실행 가능하며, 과제 1·과제 3·2.0·2.1은 지금 그대로 착수해도 됩니다.**

## 종합 판정

4차의 필수 1건과 기록 6건이 **전부 해소**됐습니다. basename 충돌을 병합 리네이밍이 아니라
188개 단일 디렉터리 재렌더로 푼 판단은 옳습니다. 코드를 하나도 건드리지 않고 문제를 없애며,
`rerender_initial_frames.py:113`이 출력 이름을 원본과 같게 고정한다는 진단도 제가 확인한 그대로입니다.
진입점을 직접 호출로 확정해 `run_screened_mimic_pipeline.py`를 수정 목록에서 뺀 것도 변경 범위를 줄인 좋은 정리입니다.

실현값 전환도 정확합니다. 제가 r4에서 계산한 52,957 / 39,729가 그대로 반영됐고,
S′ 스텝을 리터럴에서 `round(10000 × frames_S / frames_N)` 공식으로 바꾼 뒤 나온 7,502도 맞습니다.

남은 문제는 **숫자 하나**입니다. 2.2 진입 게이트 9.5 GB는 계획 자신의 디스크 원장과 맞지 않습니다.
그 값으로 진입하면 87분짜리 재렌더를 마친 직후 변환 단계가 가드에 걸려 죽습니다.

## 2. 새 디스크 규칙과 자원 합계의 타당성

### 원장 산술은 전부 맞습니다

14개 행을 처음부터 끝까지 재계산했고 모두 일치합니다. 시작 14,605에서 S′ 종료 7,852까지 오차가 없습니다.

오늘 실측 `/data` 여유는 **14,531 MiB**입니다. 계획의 14,605보다 74 MiB 적습니다.
802행이 "실행 시점에 다시 측정한다"고 규정했으므로 처리 방식은 맞습니다.

### 자원 합계도 맞습니다

| 항목 | 계획 | 재계산 |
| --- | --- | --- |
| GPU 합계 | 154분 | 1.2 덤프 3 + 2.1 10 + 재렌더 87 + 학습 3건 50 + 스모크 4 = 154 |
| GPU (S′ 포함) | 167분 | 154 + 13 = 167 |
| 디스크 합계 | 6,738 MB | 총소비 약 6,768, 회수 반영 순증 약 6,313 |

디스크 합계만 30 MiB 정도 어긋나는데 어느 값을 합계로 정의했는지에 따른 차이이고 판단에 영향이 없습니다.

### 그런데 진입 게이트 9.5 GB가 원장과 맞지 않습니다 (G1)

이것이 이번 검토의 유일한 실행 전 필수 항목입니다.

가드는 `run_act_vision_experiment.py`만이 아니라 변환 단계에도 걸려 있습니다.

```
scripts/imitation_learning/run_mimic_image_batch.py:224
    parser.add_argument("--min-free-gib", type=float, default=8.0)
```

그리고 `:334`, `:374`, `:408`에서 `check_free_space(root, args.min_free_gib)`를 호출합니다.
`check_free_space`는 `free < minimum_gib * 2**30`으로 판정하므로 8 GiB = 8,192 MiB입니다.

원장을 진입 시점 여유 `E`에 대해 역산했습니다.

| 목표 | 진입 시점 필요 여유 |
| --- | --- |
| 변환 단계가 가드를 통과 (재렌더 직후 8,192 이상) | 12,537 MiB |
| 학습 1이 시작 시점에 가드 통과 | **13,452 MiB** |
| 학습 3이 종료 시점에도 가드 위 | **14,448 MiB** |

계산 근거는 진입 → 학습 1 시작까지의 소비가 원본 감사 5 + 재렌더 4,340 + 재감사 5 + arm 데이터셋 455 +
split 455 = 5,260 MiB이고, 학습 3 종료까지의 순소비가 6,256 MiB라는 점입니다.

**계획의 게이트 9,500 MiB로 진입하면 이렇게 됩니다.**

1. 원본 감사 통과 (9,495)
2. 재렌더 188 완료 (5,155) — **GPU 87분 소모**
3. arm 변환 시작 시 `check_free_space`가 5,155 < 8,192로 즉시 실패

즉 **가장 비싼 GPU 단계를 끝낸 직후에 죽습니다.** 게이트가 보호해야 할 바로 그 상황을 통과시킵니다.

오늘 값으로는 진입 여유가 14,531 − 188 = **14,343 MiB**입니다. 13,452는 넘고 14,448에는 105 MiB 모자랍니다.
계획이 "학습 3이 진행 중 가드 아래를 스친다"고 읽은 것과 정확히 일치합니다. 원장 자체는 옳습니다.

**처방.** 777행의 게이트 숫자를 바꾸십시오.

- 최소 안전선은 **14.5 GB**입니다. 이 값이면 학습 3까지 가드 위에서 끝납니다.
- 그보다 낮고 13.5 GB 이상이면 학습 1·2는 돌지만 학습 3이 중간에 죽습니다. 이 구간에서는
  **선제 회수를 조건으로만 진입**한다고 적으십시오.
- 13.5 GB 미만이면 재렌더를 시작하지 않습니다.

계획이 이미 마련한 회수 절차가 이 문제를 풉니다. `outputs/mimic_reset_fixed_76_20260921/raw`를
**재렌더 전에** 회수하면 진입 여유가 14,343 + 1,253 = 15,596 MiB가 되어 전 구간이 가드 위에 있습니다.
지금 절차는 "그래도 부족하면"이라는 사후 조건이라, 학습 3에 도달해서야 문제가 드러납니다.
**회수 판단을 2.2 진입 시점으로 앞당기십시오.**

### 회수 후보가 하나 더 있습니다 (G4)

831-836행이 `mimic_reset_fixed_76_20260921/raw`를 첫 후보로 들고 사용자 결정 사항으로 둔 것은 타당합니다.
새 188개 파생본이 같은 설정으로 이 76개를 포함하므로 기능상 중복이라는 근거도 맞습니다.

빠진 후보는 **188개 파생 raw 자체(4,340 MiB)**입니다. arm 데이터셋 3종 변환이 끝나면 학습과 프로브는
LeRobot split만 쓰고 파생 raw를 보지 않습니다. `clipped_target_share`는 raw 목표각에서 계산하지만,
재렌더는 프레임 0·1의 영상만 바꾸고 `obs/joint_pos_target`을 건드리지 않으므로 원본 500개 raw로 충분합니다.

| 후보 | 회수량 | 재생성 비용 | 판단 |
| --- | --- | --- | --- |
| `mimic_reset_fixed_76_20260921/raw` | 1,253 MiB | 25 GPU분 | 13.8 근거라 사용자 결정 |
| 188개 파생 raw (변환 후) | 4,340 MiB | **87 GPU분** | 재감사·재변환이 필요해지면 비싸다 |

두 번째는 비용이 크므로 권하지 않습니다. 다만 학습 3이 가드에 걸렸을 때의 마지막 수단으로
후보 목록에 비용과 함께 적어 두면, 실행자가 그 자리에서 판단할 수 있습니다.

## 4. 고치지 말 것

- 방식 (A) 188개 단일 디렉터리 재렌더. 코드 변경이 없고 열 가지 매니페스트 검사가 자연히 통과합니다.
- 진입점을 직접 호출로 확정하고 `run_screened_mimic_pipeline.py`를 수정 대상에서 뺀 것.
  다섯 단정을 인자화하지 않아도 되므로 회귀 위험이 줄었습니다.
- `action_contract.py`를 손대지 않는 결정. 네 차례 검토에서 일관되게 유지된 올바른 선택입니다.
- S′ 스텝의 공식화. 배분 규칙 의존성을 제거했습니다.
- 가드를 낮추지 않고 들어가지 않으면 보고한다는 규칙(829행). 편의상 완화 금지라는 인계 조건과 맞습니다.
- 자원 스냅샷을 판단 근거에서 제외하고 각 단계 직전 측정으로 대체한 것.
- 0.5절 잠정 해제. 두 검토자의 독립 재계산이 계획 값을 재현했다는 근거에 따른 것입니다.

### 재현 방법

디스크 역산은 계획 4.3 원장의 증감값을 그대로 누적해 각 단계 시작·종료 시점의 잔여를 구하고,
`check_free_space`의 판정식 `free < minimum_gib * 2**30`에 대입해 필요한 진입 여유를 풀었습니다.
S′ 스텝은 `배치 8 × 스텝 × (close 밴드 2,520 / 학습 프레임)`을 N과 S에서 같게 두고 정수 반올림했습니다.
프레임 배분은 비례 배분 후 최대잉여법이며, 계열별 에피소드 수와 계열 내 상수 길이는
앞선 네 차례 검토에서 raw 500개 전수 계산으로 확정한 값을 썼습니다.
코드 사실은 `rerender_initial_frames.py`, `run_mimic_image_batch.py`,
`prepare_mimic_act_split.py`, `$HOME/lerobot/src/lerobot/common/train_utils.py`를 직접 읽어 확인했습니다.
`/data` 여유와 파생본 용량은 `df -BM`과 `du -sm`으로 실측했습니다.
