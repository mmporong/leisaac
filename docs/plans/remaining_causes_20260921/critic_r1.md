## 판정 지표가 퇴화 예측기에 뚫린다 (4번 기준)

`chunk_close_hit`의 정의(`:143`)는 "정답 청크에 닫힘이 있을 때 예측 청크에도 0.5 미만이 있는 비율"인데,
**어느 구간에서 집계하는지가 명시돼 있지 않다.** `gripper_rmse_by_band`와 `arm_rmse_by_band`는 구간별인데
이 지표만 구간 한정이 없다.

정답 청크에 닫힘이 있는 프레임 전체로 집계하면 이렇게 된다. demo_5 계열(675프레임, c=278) 기준으로
해당 프레임은 s=248~674의 427개이고, 그중 close 구간 `[c-30, c-1]`은 30개뿐이다.
**93%가 post-close다.** 따라서 "c 이전에는 절대 닫힘을 예측하지 않고 c 이후에는 항상 닫힘을 예측하는"
정책이 약 0.93을 받아 `:170`의 `≥ 0.8` 문턱을 통과한다.
이것이 퇴화 사례이고, 현재 문턱은 여기에 뚫린다.

`close_index_error` 중앙값 ±5 조건이 AND로 붙어 있어서 "항상 닫힘" 상수 예측기는 막힌다.
close 구간에서 예측 인덱스가 0으로 고정되면 정답 인덱스가 0~29로 퍼져 오차 중앙값이 약 -14.5가 되기 때문이다.
그 방어는 유효하다. 하지만 위의 post-close 지배 문제는 막지 못한다.

귀무모형 설계도 원칙 4(`:79` "새 판정 기준은 귀무모형부터")와 어긋난다.
`:147`의 귀무모형은 `null_gripper_rmse_by_band` 하나뿐이라 **RMSE에만 적용되고
판정 지표인 `chunk_close_hit`과 `close_index_error`에는 적용되지 않는다.**
게다가 학습 집합 평균 상수 예측기는 그리퍼 평균이 열림 쪽(0.8 부근)이라 `chunk_close_hit`이 0이 나오는,
한쪽으로만 치우친 기준이다. 반대쪽을 막는 예측기가 없다.

`close_index_error`의 조건집합도 미정의다. 예측에 닫힘이 없는 프레임의 처리와 분모가 정해지지 않았다.
예측 자체로 표본을 고르면 선택 편향 추정량이 된다.

## 과제 2.2의 두 모델은 서로 다른 검증 집합에서 비교된다

`:270`은 "각 모델에 대해 자기 검증 집합으로 1.1의 close 구간 지표를 낸다"고 한다.
두 검증 집합의 구성이 이렇다.

- 홀드아웃 모델의 검증 13개: demo_9 계열(닫힘 115, 약 273프레임) 7개 + demo_4 계열(닫힘 307, 약 692프레임) 6개
- 무작위 모델의 검증 13개: 6계열 층화 무작위

닫힘 스텝과 에피소드 길이가 계열마다 크게 다르므로, 두 수치의 차이는 모델 품질과 평가 집합 난이도가
섞인 값이다. 더 나쁜 것은 홀드아웃 모델의 검증 13개가 **무작위 모델의 학습 집합에 들어 있다**는 점이다.
어느 쪽으로 비교해도 편향된다. `:278`의 "차이 0.2 이상" 사전 등록은 비교 불가능한 두 수치에 걸린 문턱이다.

참고로 현재 seed 43 분리의 검증 15개 구성은 이렇다. 독립 재계산 결과다.

| 소스 계열 | 검증 개수 | 학습 개수 |
| --- | --- | --- |
| demo_5 | 8 | 19 |
| demo_7 | 5 | 14 |
| demo_9 | 1 | 6 |
| demo_4 | 1 | 5 |
| demo_1 | 0 | 8 |
| demo_8 | 0 | 9 |

검증 15개 중 8개가 demo_5 계열이고 demo_1·demo_8은 검증에 아예 없다.
과제 1.1의 "검증 15개 전 프레임" 집계도 절반 이상이 소스 한 개에서 나온다는 뜻이므로,
`:170`의 판정은 에피소드별·계열별 분해와 함께 보고해야 한다.

필요한 것은 두 학습에서 모두 제외한 공통 평가 집합이다. 예를 들어 계열당 2개씩 12개를 공통 평가 집합 E로 빼고,
홀드아웃 학습은 (demo_5, demo_7, demo_8, demo_1) 마이너스 E에서 55개,
대조 학습은 6계열 전체 마이너스 E에서 층화 55개로 맞추면 크기가 같고 E에서 비교 가능하다.

그리고 `:278`의 문턱은 "차이 0.2 이상 **또는** RMSE 비 1.5배 이상"이라 OR이다.
지표 두 개에 OR을 걸면 거짓 양성률이 두 배가 되고, RMSE 비는 방향이 명시돼 있지 않다.

무엇보다 **이 0.2가 잡음 바닥보다 큰지 아무도 모른다.** 13.8이 학습의 결정성을 확인했으므로
같은 데이터에서는 재현되지만, split이 다르면 데이터 구성 잡음이 들어간다.
그 잡음 크기를 재는 실험이 바로 `:107`에서 "다양성 가설을 건드리지 않는다"며 기각한 옵션 D(seed만 바꾼 split)다.
D는 가설 조작이 아니라 **B의 귀무모형**이고, 원칙 4가 요구하는 바로 그 단계다. 17분이다.
기각이 아니라 B에 흡수해야 한다.

## 기준별 나머지 지적

### 1. 원칙과 옵션의 일관성

원칙 2(`:77` "앞 단계가 뒷 단계를 불필요하게 만들 수 있으면 게이트를 건다")가 2.2에 적용돼 있지 않다.

2.2를 건너뛴다는 게이트가 사전 등록돼 있지 않다. 2.1의 결과에만 게이트가 걸려 있다(`:245`).

2.0(CPU)이 2.1의 대표 에피소드 선정을 결정하는데(`:231-239`),
`:375`의 순차 실행 순서 `1.2 → 2.1 → 3.2 → 2.2`에는 2.0이 2.1을 선행한다는 명시가 없다.

### 2. 대안의 공정성

과제 1의 옵션 B·C 기각 사유는 정직하다. B는 13.4·13.8에서 이미 한 관측이고, C는 실행 경로 변경 비용이 크다.
C를 "A가 배웠다로 나올 때 다음 후보"로 남긴 것도 합리적이다.

과제 3의 옵션 B 기각은 13.2의 `rerender_on_reset` 전례라는 실제 반례에 근거하므로 타당하다.

문제는 과제 2다. 위에서 적은 대로 옵션 C의 기각 사유가 더 싼 변형에 적용되지 않고,
옵션 D는 잘못된 이유로 기각됐다.

### 3. 위험 대비의 명확성

인덱스 공간이 섞여 있다. `:136`은 `c`를 raw 인덱스로 정의하고 `:135`는 청크를 LeRobot 프레임 `s`로 정의하는데,
`:137`의 구간 `[c-30, c-1]`이 어느 공간인지 적혀 있지 않다.
산술상 `s` 공간으로 읽으면 정확히 맞는다. `s = c-1`의 청크가 raw `c`부터 시작하므로 닫힘이 인덱스 0에 오고,
`s = c-30`이면 인덱스 29에 온다. 맞는 정의지만 적혀 있지 않은 것이 문제이고,
단위 테스트 항목에 구간 인덱스 공간 검사가 없다(`:417`은 닫힘 인덱스 계산과 `target[0]` 함정만 다룬다).

에피소드 끝에서 30스텝 청크가 잘리는 경우의 처리도 미정의다.
675프레임 에피소드의 `s = 674`는 raw 675~704를 요구한다.
close 구간에는 영향이 없지만 baseline 구간 지표에는 영향이 있다.

`:164`는 기존 모델에 대해 체크포인트만 바꾼다고 적었는데, `--split-root`를 고정 데이터 split으로 유지하면
원본 데이터로 학습한 모델을 고정 프레임 데이터에서 평가하게 된다.
close 구간에는 영향이 없지만 baseline 구간 RMSE는 교란된다. 어느 split-root를 쓰는지 사전 등록이 필요하다.

`:153`의 raw 부경로는 uint8 HWC이고 LeRobot 주경로는 float [0,1] CHW다.
`scripts/imitation_learning/serve_lerobot_act.py:117-119`의 `permute(2,0,1).unsqueeze(0).float().div(255.0)`가
학습·추론의 기준 전처리다. 두 경로의 전처리 동등성 검사가 사전 등록돼 있지 않다.

이름 충돌도 실제 위험이다. `:187`의 `shard_009/demo_9`는 **소스 demo_5 계열**(닫힘 278)이고,
`:238`의 "demo_9 계열"은 **소스 demo_9**(닫힘 115)다.
같은 문서 안에서 `demo_9`가 서로 다른 두 대상을 가리킨다.

2.0의 proxy 강등 경로(`:227`)는 좋은 사전 등록이다. 다만 귀속이 게이트 artifact일 경우
2.1·2.2를 어떻게 할지는 정해져 있지 않다. 그것이 실제로 일어난 실패 양상이다.

### 4. 판정 기준의 검증 가능성

위의 별도 절에 적었다. 요약하면 세 가지다.
구간 한정 누락으로 `chunk_close_hit ≥ 0.8`이 퇴화 예측기에 통과한다.
귀무모형이 RMSE에만 걸려 있어 판정 지표를 덮지 못한다.
2.2의 0.2/1.5배는 비교 불가능한 두 집합에 걸려 있고 잡음 바닥이 측정되지 않았다.

적용 범위만 RMSE에서 판정 지표로 넓히면 된다.

실행 가능성은 좋다. 작성 패스와 검증 패스를 다른 실행으로 나누고 검증 패스가 쓰기를 하지 않는다는 규정(`:415`),

### 6. 자원과 순서

시간과 디스크 산술은 현실적이다. 2.2의 1,040 MB는 실측 split 78 MB 두 개와 학습 440 MB 두 개에 맞고,

작업 순서의 게이트 설계는 대체로 좋다. 비용 오름차순이고, 재생성과 리더 재촬영을 마지막에 둔 것도
