# SO101 해상도 개선·저장 공간 정리 인계

후속 상태: 500회·277,447프레임 생성·변환·병합 완료.
[ACT 400/100 분리·학습·평가 인계](HANDOFF_ACT_VISION224_500_20260913.md)로 이어진다.

## 목적과 변경 범위

기존 원본 리더 시연 10회에서 MimicGen 성공 데이터를 새 해상도로 생성한다.
이 단계는 **데이터 증강**이며 ACT 학습이나 강화학습의 성공을 뜻하지 않는다.
현재 큐브(시각 외곽 약 3cm, 충돌 외곽 약 3.0154cm), 로봇, 카메라 위치,
물체 초기 위치 분포, 박스, 놓기·그리퍼 해제 성공 판정은 변경하지 않는다.
실물 로봇을 구동하지 않는다.

| 항목 | 기존 실험 | 새 opt-in 프로필 |
| --- | --- | --- |
| 앞·손목 카메라 렌더 | 320×240 | 640×480 |
| 저장·ACT 입력 | 84×84 | 224×224 |
| 영상 축소 | OpenCV AREA | 동일한 OpenCV AREA |
| 행동 라벨 | 다음 관측 관절 위치 | 동일, 마지막 프레임은 마지막 관절 위치 반복 |
| 생성 목표 | 기존 100 성공 | 별도 500 성공, 25회씩 20묶음 |
| 실패 저장 | 원시 실패 HDF5도 저장 | 실패 횟수는 기록, 실패 영상 전체 저장은 끔 |

해상도 개선은 작은 큐브와 그리퍼의 시각 정보를 더 남기려는 가설이다.
정책 성공률이 올라가는지는 별도 학습·평가 전까지 알 수 없다.
기존 84×84 모델은 224×224 입력 모델이라고 간주하지 않으며 서버가 설정 불일치를 거부한다.
기존 기본값은 그대로 보존했다.

## 공간이 부족했던 이유와 정리

정리 전 `/data` 파티션은 약 132GiB 중 111GiB 사용, 21GiB 여유였다.
이 저장소 데이터 약 30GiB, 모델·출력 약 14GiB, Isaac 실행 환경 약 25GiB가
주요 원인이었다. 같은 원본의 관절 행동 변환본·저해상도 파생 HDF5가 중복되었다.

삭제한 것은 다운로드 캐시 약 1.6GiB와 재생성 가능한 파생 HDF5 3개 약 5.5GiB다.
정리 직후 여유 공간은 약 28GiB다. 새 실행이 진행되면 이 수치는 다시 줄어든다.
원본 시연, 원시 성공·실패 생성 데이터, canonical next-observed 데이터,
학습 모델, 포트폴리오 영상은 보존했다. 무관한 프로젝트·실행 환경은 지우지 않았다.

정확한 경로·크기·SHA256·대응 관계는
[정리 검증 기록](evidence/storage_cleanup_20260913.json)에 있다.
원본과 파생 파일은 demo 번호 정렬이 달라 완전한 관절·행동 배열로 대응시켰다.
이미지는 각 에피소드 처음·중간·끝 프레임을 표본 대조했다.
삭제 파일은 휴지통 복원 대상은 아니며 보존 원본에서 다시 변환할 수 있다.

## 실행과 재개

리포는 Linux에서 `/data/lim/leisaac`에 있다. 아래에서는 환경 경로를 직접 지정한다.

```bash
cd "/data/$USER/leisaac"
"$HOME/miniforge3/envs/lerobot/bin/python" scripts/imitation_learning/run_mimic_image_batch.py \
  --input datasets/pick_cube_into_box_annotated_wrist_10_20260911.hdf5 \
  --output-dir outputs/mimic_vision224_500_20260913 \
  --isaac-python "/data/$USER/conda-envs/leisaac/bin/python" \
  --total 500 --chunk 25 --seed-start 6100 --min-free-gib 8
```

GPU 메모리 실측 장치는 RTX 5050 Laptop **8GB**다. 과거 대화의 12GB 가정은 사용하지 않는다.
먼저 별도 pilot 출력 폴더에서 3회 생성·변환을 검증한 후 본 배치를 실행한다.

- 500은 시도 횟수가 아니라 성공 데이터 목표다. 묶음마다 최대 250회 시도한다.
  `--max-attempts-per-success` 기본값은 10이다. pilot은 이전 상한 15회 안에서
  3성공/11시도를 기록했다. 본 배치는 낮은 생성 성공률에도 여유를 두되 무한 재시도하지 않는다.
- 성공 HDF5를 224 이미지·다음 관측 관절 행동으로 직접 LeRobot 변환한다.
  별도 관절 행동 HDF5 중간 복사본은 만들지 않는다.
- 각 묶음의 최종 변환 provenance, 원본 SHA, 개수·프레임·이미지 모양을 검증한다.
- 모두 끝나면 `lerobot_all`로 합친다. 원시 성공 HDF5와 묶음별 LeRobot도 남는다.
- 여유 공간 8GiB 미만이면 중단하고 부분 결과를 보존한다. 이 기준은 예약 공간이나
  쓰기 원자성을 보장하지 않는다. 생성 중 최대 60 시뮬레이션 step 간격으로 확인한다.
- 출력 폴더의 `STOP` 파일을 발견하면 **다음 묶음 시작 전** 멈춘다.
  즉시 정지 버튼이 아니며 이미 시작한 묶음은 끝까지 진행한다.
- 동일한 명령으로 재개할 수 있지만 완료된 묶음만 재사용한다. 부분 생성/변환,
  원본·코드·계획 불일치, 이미 존재하는 미완료 병합 출력은 덮어쓰지 않고 오류로 남긴다.
- `progress.json`은 전체 상태, `generator_progress.json`은 현재 묶음 성공·실패·시도 횟수,
  `logs/`는 생성·변환 로그다. `status=complete` 전에는 500회 완료가 아니다.

배치 스크립트는 LLM 호출 없이 시뮬레이터를 실행한다. 매 에피소드마다 Codex가
로그를 읽을 필요가 없으므로 토큰 사용을 줄인다. 설정·점검·오류 분석 대화에는
토큰이 들며, 시뮬레이션에는 별도로 로컬 GPU 시간과 디스크가 든다.

## 데이터 생성 이후

1. 성공 데이터 수와 영상, 관절 연속성, 놓기·해제 조건을 확인한다.
2. 에피소드 단위로 학습/검증을 분리하고 정규화 통계는 학습 데이터만으로 만든다.
3. 224×224 ACT를 학습하고 동일한 224 입력·640×480 렌더로 평가한다.
4. 기존과 같은 평가 초기 상태에서 집기/들기/놓기 실패를 구분한다.
5. 충분한 시뮬레이션 검증 후 별도 실물 검증을 준비한다. 강화학습은 이 단계의
   자동 후속 작업이 아니며 별도 정책·보상·안전 조건을 설계해야 한다.

이번 변경은 데이터 수와 해상도를 함께 바꾸므로 기존 100회와 직접 비교해서
“500회만의 효과”라고 말할 수 없다. 데이터 수 효과를 보려면 새 224 데이터의
100회 부분집합과 500회로 같은 학습·평가 조건을 비교한다.

## 이번 실행 검증

- CPU 회귀 테스트 55개, 변경 실행 파일 Python 컴파일, `git diff --check` 통과.
  독립 리뷰에서 원시 행동 NaN/Inf 검사와 재개 manifest 대조 누락을 보강했고
  실행을 막는 문제는 남지 않았다. 전체 정적 타입 검사는 Isaac 모듈 검색 경로와
  h5py 타입 설정 공백 때문에 clean 통과로 주장하지 않는다.
- pilot seed 6000: 총 11시도 중 3성공·8실패. 성공 3회·1,803프레임의 생성,
  LeRobot 변환, 통합 데이터 병합까지 완료했다. 실패 HDF5는 생성하지 않았다.
- 두 카메라 영상은 uint8 224×224×3이다. LeRobot에서 9개 표본을 실제 디코딩해
  3×224×224 입력과 다음 관측 관절 행동 라벨을 대조했다.
- 별도 ACT 2스텝 GPU 학습을 실행하고 224 입력 체크포인트로 CPU 추론 서버의
  reset/predict/shutdown을 검증했다. 결과 행동 6개는 모두 유한했다.
  **2스텝 모델은 배선 검증용이며 집기 정책으로 사용할 모델이 아니다.**
- 성공 원시 HDF5는 69,323,565 bytes, LeRobot 묶음과 병합본은 각각 약 4.4MiB다.
  같은 길이·압축률이면 500회 저장은 약 12GiB로 추산된다. 길이 분포, 중간 파일,
  이후 학습 체크포인트는 별도이므로 8GiB 공간 제한을 유지한다.
- 224 영상에서 큐브·그리퍼 윤곽이 84 축소본보다 선명한 것을 눈으로 확인했다.
  이 비교는 같은 새 640 렌더에서 만든 84/224 비교이며 과거 실행의 픽셀 대조는 아니다.
- 검토 중 pilot을 실행했으므로 최초 plan SHA와 최종 소스 SHA를 분리 기록했다.
  이후 입력값 검사·중단 상태 보존·manifest 기록을 추가 보강했다.
- 보강한 최종 코드도 seed 6001에서 별도 실행해 2시도 중 1성공·254프레임의
  생성·manifest 대조·변환·병합을 완료했다. 이 최종 스모크는 첫 pilot과 별도 보존한다.
